# Desk32

[English](README.md) | [日本語]

**Desk32** は、最高品質のモニタリング環境をローカルに再現する、オーディオマニア向けスタジオコンソール型ミュージックプレーヤー（Linux専用）です。

> **注意:** Desk32 は純粋な音質評価・リファレンス試聴のためのスタジオコンソールであり、DJ用同時ミキシング機能、ビート同期、クロスフェーダー等は明確に除外しています。

---

## 主要な特徴

- **Reference Deck System:** メイン画面に 4Deck（Deck A〜D）を常時表示。独立した Transport・Seek 位置を保持し、ワンタッチ比較試聴を実現。「通常切り替え（位置保持）」と「比較切り替え（切替元Pause＋切替先へサンプル/ms単位シーク＋Deck別オフセット調整）」の2モード制。
- **フォルダ連続試聴（Folder Session）:** フォルダ直下の音源を自然順スナップショットで先頭から再生。肥大化したPlaylist機能に頼らず、アルバムやフォルダごとの順次試聴を補助。
- **3系統のOutput Path（段階的実装）:**
  1. *Listening Path*: リスニング専用補正（ヘッドホン/スピーカー/部屋音響補正）。
  2. *Render Monitor Path*: リスニング補正混入なしでマスタリング結果そのものを試聴。
  3. *Render / File Output Path*: オフラインファイルレンダリング経路（Phase 4）。
- **内部処理 64-bit float 基準:** 内部ミキサー・サミング・内蔵DSPの基本演算は IEEE 754 64-bit 倍精度浮動小数点（double precision）を採用。
- **スタジオコンソール型UI:** WQHD (2560 × 1440) フルスクリーンを標準ターゲットとし、トラック波形表示必須、32-band GEQおよび左右各12バンドPEQの非破壊全面切り替えを搭載。
- **完全ローカル完結:** ネットワーク通信、テレメトリ、クラウド同期、オンラインAI機能を一切排除。ジャケット画像（Artwork）の抽出・キャッシュも行わない完全プライバシー設計。
- **非同期操作ログ（Log Tab）:** SQLiteへの非同期構造化記録およびJSONLエクスポート。Audio Threadを一切ブロックしない設計。

## 技術スタック

- **開発言語:** C++20
- **GUIフレームワーク:** Qt 6 (Qt Quick / QML / Scene Graph)
- **音声バックエンド:** PipeWire (標準・最優先) / JACK (早期対応) / ALSA direct (後続対応)
- **ビルドシステム:** CMake (≥ 3.22) & Ninja
- **対象プラットフォーム:** Linux デスクトップ (X11 / Wayland) — 基準環境: CachyOS + COSMIC Desktop Environment

## ソースコードからのビルド

Desk32 はソースコード公開のみで配布されます。依存ライブラリは各自のディストリビューションのパッケージマネージャから導入してください。

### 前提パッケージの導入 (Arch Linux / CachyOS)

```bash
sudo pacman -S --needed base-devel cmake ninja pkgconf qt6-base qt6-declarative qt6-tools \
    pipewire jack2 alsa-lib sqlite flac libvorbis opus ffmpeg libsoxr taglib vulkan-headers vulkan-icd-loader
```

> **補足:** メタデータの読み書きには `taglib` と `pkgconf`（CMake 構成時の `pkg-config` 検出に必須）が必要です。

### ビルドとテストの実行

```bash
# CMake Preset を使用した構成 (GCC & Ninja デバッグ)
cmake --preset default

# ビルド実行
cmake --build --preset default

# 単体テストの自動実行
ctest --preset default
```

Clang コンパイラでビルドする場合:

```bash
cmake --preset clang-debug
cmake --build --preset clang-debug
ctest --preset clang-debug
```

## 既知の問題

### ウィンドウを表示したまま再生を続けるとメモリ使用量が増え続けます

Desk32 を Wayland 環境で使い、ウィンドウを表示したまま再生を続けると、
プロセスのメモリ使用量（RSS）が時間に対してほぼ線形に増加します。
開発環境での実測では、12時間の連続再生で **+54.8 MB/h**（335.9 MB → 974.3 MB）
でした。プロセス自体は安定して動作し続け、再生や音声への影響（XRUN）は
同条件で確認されていません。ウィンドウを最小化すると増加は止まります。

#### 原因

Desk32 本体のコードではなく、描画プラットフォーム側の不具合です。
調査の結果、増加分の主因（約 +49.3 MB/h）は、画面のフレーム描画のたびに
Qt Wayland の EGL 統合が発行する `wl_display.sync` の応答イベントが、
libwayland-client の内部で1件あたり216バイトのまま滞留し続けることでした
（フレームレート約63.4回/秒 × 216バイト）。このイベントキューの処理は
アプリケーション側からは操作できず、Desk32 のコードでは根本的に
修正できません。対象キューのハンドルがアプリに公開されていないためです。

#### 調査の経緯（要約）

1. 9.8時間および12時間の長時間再生テストで、約 +54〜55 MB/h の線形増加を再現。
   増加は曲の切り替えとは無相関で、スレッド数・ファイルディスクリプタ数は安定。
2. 短時間の条件切り分けで、最小化したアイドル状態では増加しないこと、
   DSP チェーンを全バイパスしても増加が変わらないことを確認し、
   原因を「表示を伴う描画」側に絞り込み。
3. heaptrack によるヒープ計測で、増加の94%が libwayland-client の
   `wl_display_read_events` 内部の単一の確保サイト（216バイト、フレームと
   同じ頻度で確保され、終了時まで解放されない）であることを特定。
   Desk32 自身のコードはこの経路に現れないことを、スタックトレースでも確認。
4. `WAYLAND_DEBUG=client` のプロトコルログで、フレームあたりのイベントを
   実数で数え、上記の sync コールバックが 63.42回/秒で届くこと、その量が
   メモリ増加量と一致することを確認。

#### 影響と回避策

- 影響は「表示したまま再生を続けた時間」に比例します（実測環境で約 +49 MB/h が
  本件分）。長時間再生しない使い方や、最小化して聴く使い方では問題になりません。
- XWayland（`QT_QPA_PLATFORM=xcb`）での起動では発生しません
  （2026-11-14 実測：30分再生でメモリ増加はほぼゼロ。Wayland 経路が
  発生の必要条件であることを確認しました）。
- 描画バックエンドを Vulkan に切り替えた場合も発生しません
  （2026-11-14 実測：同条件でほぼゼロ。問題が EGL の描画経路にあることの
  裏付けです）。
- **現在の構成（2026-11-16 決定、2026-11-17 実装）**：Desk32 の既定バックエンドは Vulkan です
  （この問題は発生しません）。Vulkan が使えない環境では OpenGL に
  フォールバックしますが、その場合は特に NVIDIA＋Wayland の組み合わせで
  本件が発生しうるため、長時間再生ではご注意ください。OpenGL での利用時は
  上記の xcb 起動も回避策になります。
- Qt またはグラフィックスドライバ（EGL）側の修正で解消する可能性があり、
  依存ライブラリの更新時には再確認します。

#### 確認した環境

- OS：CachyOS、デスクトップ環境：COSMIC（Wayland）、GPU：NVIDIA（EGL）
- Desk32 ビルド：コミット `94960aa`（2026-11-12）
- 他の環境（異なるコンポジタ、GPU、Qt の版）では、発生の有無や増加量が
  異なる可能性があります。
